# 設計書の変更

変更：$ARGUMENTS

`設計書.md` は仕様の正本。実装より先に設計書を直す。設計書の文体（です・ます、表、節番号での参照）に合わせる。

## 手順
1. **変更点を確かめる**：何を、どの節で、なぜ変えるか。利用者の決定でないもの（自分の推測）は書かない。決まっていなければ AskUserQuestion で聞く
2. **本文を直す**：該当の節だけでなく、同じ事柄を書いている節をすべて直す。探し方の例：
   - 数値は全文を Grep（例：「600」「4,500」「10分」「3回」「4時」）
   - 用語は Grep（例：「天井」「ホーム・スワイプ枠」「信頼時刻」）
   - よく重複する組み合わせ：5.3 と 7.3（天井）、5.1・5.2 と 7.4（更新回数・枠）、5.4・6.1・6.3（強制解除）、7.1・7.5・8章「定数」（レア度・コイン）、6.2 と 9.3（常時ロック）、5.6 と 10章（10分待ち）
3. **相互参照を確かめる**：節を足す・消す・番号を変えたら、本文中の「（7.4）」「（6.4）」などの参照をすべて Grep して合わせる
4. **数値を変えたら**：
   - 7.5「ガチャの価格の決め方」の表を計算し直す（ご褒美が出る確率、価値の期待値 = 300 × 分 × 倍率）
   - 7.4 の出現率の表（ガチャ／ホーム・スワイプ）を合わせる
   - 8章「定数」と「Settings」の初期値を合わせる
5. **11章 未決事項**：決まったものは `[x]` にして「→ 決定内容」を書く。新しく出た未決事項は `[ ]` で足す
6. **冒頭と 12章**：冒頭の「最終更新」を今日の日付にする。版を上げるか（大きな変更）、今の版に追記するかを利用者に確認する。12章に変更点を「何を（節）」の形で1行ずつ書く
7. **リポジトリ内の同期**
   - `domain/src/main/kotlin/com/dopagaki/detox/domain/Rules.kt` の定数（と、その値を確かめるテスト）
   - `CLAUDE.md` の設計書の索引・用語対応表・不変条件
   - `.claude/skills/implement-domain/SKILL.md` のテストケース
   - `.claude/agents/spec-reviewer.md` のチェックリスト
   - UI の文言を変えたら、該当画面の `strings.xml`
   - 見た目に関わる変更なら `docs/design-system.md`（designer を通す）
8. **確かめる**：`./gradlew :domain:test`。変更の要約（直した節、同期したファイル）を利用者に返す
