# ドメインロジックの実装

対象：$ARGUMENTS

## 置き場所と決まり
- `domain/src/main/kotlin/com/dopagaki/detox/domain/` に置く。`:domain` は純 Kotlin（JVM）で、Android の API を使わない（使えない）
- 数値はすべて `Rules.kt` から読む。コインの倍率は整数の百分率（`rarityMultiplierPercent`）で持ち、`単価 × 分 × 倍率% / 100` を整数で計算する。設計書 8章の「定数」と「Settings」の初期値が正本。値を変えるときは先に `/update-spec`
- 時間は `TrustedClock`（`now(): Instant`）を引数・コンストラクタで受け取る。`System.currentTimeMillis()`・`Instant.now()`・`LocalDate.now()` を使わない
- 乱数は `kotlin.random.Random` を受け取る（テストではシードを固定するか、確率の境界を作る自作の Random を渡す）
- 日付は `DayKey`（4時区切り）で扱い、タイムゾーンは引数で受け取る
- Room・DataStore への保存は `:app` の `data` 層。ドメインは保存の仕方を知らない（必要ならインターフェースを `:domain` に置き `:app` で実装する）
- テストは `domain/src/test/kotlin/...`。時間は `FakeTrustedClock`（`domain/src/test/.../FakeTrustedClock.kt`）で進める

## 手順
1. 設計書の該当節を読む（下の表）。曖昧な点は実装前に AskUserQuestion で聞き、決まったら `/update-spec` で設計書に書く
2. 下の「テストケース」から該当するものをテストに起こす（境界値を含める）。テストが落ちることを確認する
3. 実装する。`./gradlew :domain:test` を通す
4. spec-reviewer に、変更したファイルと設計書の節を列挙してレビューを頼む。高・中を直す

## テストケース（設計書から）

### コイン（7.5）
- できた：机の上を片付ける 5分・N → +500／ストレッチ 10分・N → +1,000／紙の本 20分・R → +2,500／英語の長文 40分・SR → +6,000／英単語 15分・R → +1,875
- 一部できた：15分・R → 937（1,875 の半分を切り捨て）
- できなかった・強制解除・ご褒美の完了 → 0。コインは減らない
- ご褒美をホーム・スワイプ・あとでから始める：SNS 10分・SR → −4,500／ゲーム 20分・SSR → −12,000。ガチャ経由 → 0
- 所持コインが足りないご褒美は始められない（−にならない）
- 連続日数ボーナス：その日最初の完了でだけ付く。3日目 → +300、10日目 → +1,000、15日目 → +1,000（上限）
- 初回起動ボーナス 3,000 は1回だけ

### 抽選（7.1〜7.4）
- 重み `w = p × (1 + 0.1 × min(d, 7)) × c`：p=4・d=10 → 6.8／直前と同じ → ×0.2／ご褒美の直後のご褒美 → 0
- ご褒美の次の1回はやることだけから出る
- ご褒美の1日上限（初期値2回）に達したら、ガチャの抽選対象から外れる
- 静かな時間帯（23時〜6時）はご褒美が出ない。境界：22:59 は出る、23:00 は出ない、6:00 は出る（日をまたぐ範囲として扱う）
- 枠が空：SR を引いて SR の候補がなく R と SSR に候補がある → R（同じ近さなら下）。天井確定中は、出せるご褒美がある枠から選ぶ
- フィード：重複なしで20件。候補が20件未満なら候補数まで。時間帯タグ（朝・昼・夜）が合うものが先。ご褒美の出現率はガチャの 1/10
- 「あとで」に保存したものはホームの先頭

### 設計書で未定の点（該当する実装の前に AskUserQuestion で聞き、/update-spec で設計書に書く）
- 8章 Settings の unlockWaitMin・unlockGraceMin・homeRewardRatio・refreshLimit・refreshWindowMin・dayStartHour を利用者が変えられるか。変えられるなら 5.6 の表でどちらの向きを10分待ちにするか（推奨：MVP では固定）
- 静かな時間帯のオン・オフの持ち方（8章に項目がない）と初期値（推奨：`quietEnabled` を足し初期値オン）
- 静かな時間帯の境界（推奨：23:00 を含み 6:00 を含まない）と、判定する時点（抽選のときか、始めるときか）
- 一度も実施していないミッション（lastDoneAt が null）の重みの d（推奨：上限の 7）
- 7.4 の「SRのうちご褒美 6%」の意味と、ホーム・スワイプで ÷10 にする方法（推奨：ガチャと同じ方法で抽選し、ご褒美が出たら確率 0.9 でやることから引き直す）
- 8章 Settings の rewardAppLock・allowForceUnlock・allowPause・dailyGoalMin の初期値

### 天井（7.3）
- 15分以上のやることを「できた」で5回続けると、次のガチャ（単発・10連）がご褒美確定。10連では少なくとも1件がご褒美
- 一部できた・できなかった・強制解除 → カウント0
- ご褒美ミッション → 数えず、0にも戻さない
- 上限到達・静かな時間帯でご褒美を出せないとき → 天井を使わず持ち越す（pityReady のまま）
- 未定：15分未満のやることを「できた」で終えたとき（数えないが0にも戻さない、と読める）と、15分未満の「一部できた」でリセットするか → 実装前に利用者に確認する

### 更新回数（7.4）
- ホームの引っ張って更新とスワイプの次の20枚を合わせて、直近60分に3回まで
- 0分・10分・20分に更新 → 30分の4回目は不可、「次の更新まで」は 30:00。60:00 ちょうどで可（いちばん古い更新から60分）
- 信頼時刻で数える（端末の時計を戻しても回数は戻らない）

### 信頼時刻（6.4）
- 同じ起動の間に端末の時計を1時間進めても、信頼時刻は進まない
- 再起動（bootCount が変わった）＋ネットワーク時刻あり → ネットワーク時刻が基準（source=network）
- 再起動＋ネットワーク時刻なし → 最後に保存した信頼時刻が基準（電源オフの間は数えない、source=carried）
- ネットワーク時刻が取れるようになったが今の信頼時刻より過去 → 信頼時刻は戻さない
- 初回起動でネットワーク時刻なし → 端末の時計（source=device）

### 日付の切り替え（6.4）
- 3:59 は前日の dayKey、4:00 から当日
- タイムゾーンを変えて同じ日が2回来ても、切り替えは24時間に1回まで。dayKey は後戻りしない

### 実行中・強制解除（5.4、6.1、6.3）
- 強制解除のボタンは残り 10:00 ちょうどなら出す、9:59 なら出さない
- 強制解除の待機は10分。取り消せる。待機中も残り時間は進む。10分たつとセッションは aborted・コイン0・連続記録は維持・天井カウント0
- 一時停止は1回だけ・最大5分・5分で自動再開。止めた分だけ endsAt が後ろへずれる。解除の待機中は一時停止できない
- 起動時に running かつ endsAt が未来のセッションがあれば、実行画面から再開する。endsAt が過去なら完了報告へ

### 10分待ち（5.6）
- 5.6 の表の左列（有利な変更）は PendingChange（appliesAt = 依頼時刻 + 10分）、右列（厳しくする変更）は即時
- 待機中に別の有利な変更をすると、それぞれ別に10分
- 取り消すと status=cancelled、反映されない
- 常時ロックの強制解除：10分待ってから対象アプリを30分だけ通し、その後また常時ロック
